# 7. Axios

> 임의 목업 데이터를 OpenWeatherMap API 데이터로 바꾸고, 예보·대기오염·일출/일몰 API를 상세 화면에 붙임

## 과제 요구사항 정리

1. OpenWeatherMap API로 실제 날씨 데이터를 가져와 적용
2. OpenWeatherMap의 다른 API를 추가해 기능 확장
3. 기타 외부 API를 추가해 기능 확장

파일: `src/services/weatherApi.js`, `src/stores/weatherStore.js`, `src/data/cities.js` 외 12개

## 과제 세부 개발내용

- **도시 데이터 분리**: 실습6까지 정적데이터로 운영하다가 API 데이터가 들어오면서 수치가 매번 바뀌게 되어 이에 대한 처리가 필요했고, 이를 해결하기 위해 `data/cities.js`는 이름·국가·국가코드만 든 "브라우징용 목록"으로 남기고 날씨는 store가 따로 채우는 구조로 나눔. 도시는 국내 13개에서 16개국 91개로 확장 (UI구현을 위한 개인적인 욕심)
- **Geocoding → 현재날씨 조회** ① 필름 매칭 서비스를 위한 예보·대기오염·일출/일몰 API가 전부 좌표를 요구하고 있으므로 Geocoding 방식을 찾아봄 ② OWM 공식 문서 조회 결과 `?q=` 직접 조회를 deprecated로 두고 Geocoding API를 권장하여 이번 과제에서 `{name},{countryCode}`로 좌표를 구하고 그 좌표로 `/data/2.5/weather` 호출, 좌표는 모듈 캐시로 재사용하는 코드 도입
- **`mock` 데이터 폴백**: API 키가 미등록되어 있거나 호출에 실패하면 도시 이름을 시드로 만든 `mock` 데이터로 조용히 내려가는 현상을 확인했고 이를 해결하기 위해 모든 응답에 `source`(`live`/`mock`)를 포함시켜 상세 화면에서 배지로 구분 표시함
- **비동기 로딩 상태**(`stores/weatherStore.js`): 실습6까지 더미데이터를 써서 몰랐는데 실제로 api호출을 해보니 Geocoding·날씨 호출이 오가는 동안 값이 없는 구간이 발생하여 이를 해결하기 위해 날씨가 아직 없는 카드는 "불러오는 중" 표시로 두고 `Promise.all`을 사용해서 병렬 조회를 구현, 한 세션 안에서는 도시별로 한 번만 부르도록 캐싱
- **호출량 억제**: 무료 api의 호출량 제한은 분당 60건이므로 검색 대시보드·전체 도시 보기는 화면에 실제로 올라온 도시(검색 결과, 없으면 방문·즐겨찾기 + 국가별 대표 도시 약 16개)만 조회하고, 91개 전체는 도시 찾기 팝업에서 이름만 나열하는 방식으로 우회함
- **`weather[0].main` → 3버킷 매핑**(`utils/weatherBuckets.js`): 카드 표시와 한 줄 필름 추천이 맑음/흐림/비 3개 값만 써서, OWM의 세밀한 코드(Clear/Clouds/Rain/Snow/Mist…)를 3개로 좁히는 함수를 둠. 버킷 옆 괄호에는 구름 계열(Clear/Clouds)이면 구름량 %를, 비·눈·안개면 OWM 원본 설명(`온흐림`/`보통 비` 같은 제공 라벨)을 그대로 표시
- **store 분리**: 서로 성격이 다른 데이터를 합치지 않고 journeyStore(즐겨찾기·방문 이력)와 weatherStore(API 응답 캐시)로 나눔.
- **도시 식별 방식 변경**: 현재 선정한 데이터에서 도시 이름이 겹치는 경우가 없으므로 이름값 자체를 식별키로 활용
- **추가 API — 5일/3시간 예보 + 대기오염**: 상세 화면에서 3시간 예보와 대기오염 응답을 합쳐서 예보 슬롯마다 가장 가까운 대기오염 예측치를 붙임. 이걸 입력으로 "사진 찍기 좋은 시간"을 계산함(광량 높고 공기오염도가 낮은 시간대 탐지)
- **기타 외부 API — sunrise-sunset.org**(`services/sunApi.js`): 무료 공개 API인 sunrise-sunset에서 일출·일몰·시민박명 시각을 받아, 도시 현지 시각(현재 날씨 응답의 타임존 오프셋 사용)으로 골든아워·블루아워 구간을 상세 화면에 표시함
- **노출값(EV) 기반 필름 계산**: API데이터를 들여다 보던 중 광량 조건을 보다 상세히 반영 할 수 있겠다고 판단되서 도입한 기능으로, 광량 조건 Sunny 16 차트의 EV100 값으로 바꾸고, 사용자가 고른 조리개·최대 셔터스피드로 "과다노출 없이 쓸 수 있는 최대 ISO"를 구해 필름 14종을 감도순으로 필터링함
- **ESC 상호작용 추가**: 화면 작동 테스트 중 선택된 도시나 지역을 취소하는 이벤트의 필요성을 느껴서 ESC 키입력을 이벤트로 받아서 해당 로직이 작동하도록 연결함

## 추가 확장 아이디어

1. 실데이터 연동에서 부딪힌 좌표·매핑·로딩 문제 정리
2. 노출값(EV) 기반 필름 추천
3. 사진 촬영 조건 API 조합

### 좌표·매핑·로딩

- **좌표**: 데이터에 위경도를 하드코딩하는 방법과 Geocoding으로 필요할때 받아 캐싱하는 방법 중 후자를 택함. 91개 도시의 좌표를 손으로 채우면 검증이 어렵고, OWM 공식 문서가 권장하는 방식이어서 채택하였으나 좌표 캐시가 모듈의 수명과 같이 작동, 새로고침하면 Geocoding을 다시 함
- **로딩**: 카드 단위로 "불러오는 중"을 비동기로 실행, 먼저 완료된 카드들부터 자연스럽게 갱신되도록 함

### 노출값(EV) 계산

보통 많이 쓰이는 노출값 계산방법을 반영하여(t100 = 조리개² / 2^EV100, maxIso = 100 × t100 × 최대셔터분모) 셔터스피드와 조리개값에 따라 적용할 수 있는 필름의 감도값을 역으로 추산하도록 설계함

### 사진 촬영 조건

예보(구름량)와 대기오염 예보(AQI)를 슬롯 단위로 합쳐 점수화 한 뒤 일출/일몰 API로 골든아워·
블루아워를 UI로 함께 볼 수 있도록 배치해서 "언제 찍으러 나갈지"를 한 화면에서 판단 가능하도록 만듦

## 의문점 정리

첫 진입에 Geocoding + 현재날씨로 도시당 2건, 대표 도시 16개면 32건이 한 번에 나감.
무료 API 리밋값인 분당 60건보다 적은 양이기는 하지만, 상세 화면(예보·대기오염·일출 3건 추가)까지 겹치면 여유가 크지 않으므로 개선하면 좋겠다고 판단됨.
localStorage에 응답을 캐싱해 새로고침 후에도 재사용하는 방법, 또는 좌표만이라도
데이터에 넣어 Geocoding을 없애는 방법 등을 추가로 검토 후 여력이 남으면 반영하겠음
