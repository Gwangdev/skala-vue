# 8. UI Libraries

> 지역별 도시 찾기 팝업과 필름 확대 뷰를 Element Plus `el-dialog`로 처리하고, 검색 대시보드와 전체 도시 보기를 한 화면으로 합치면서 날씨 배너·필름 스트립을 붙임

## 과제 요구사항 정리

1. **외부 UI Library 선정**: Vue 3 생태계의 라이브러리 중 하나를 골라 도입
2. **Weather 앱에 적용**: 실습7까지 만든 화면에 자유롭게 반영

파일: `src/main.js` 외 12개

## 과제 세부 개발내용

- **검색 대시보드와 전체 도시 보기 병합**: 실습5에서 `/cities`로 떼어냈던 전체 도시 보기가 실습7에서 도시를 91개로 늘리며 검색 대시보드의 목록과 사실상 같은 내용을 보여주게 되서 리팩토링함. 두 화면을 검색 대시보드 하나로 합치고 `/cities` 라우트와 전용 뷰(`WeatherCitiesView`)를 제거했음
- **라이브러리 선정 — Element Plus**: `main.js`에 전역 등록 + 기본 CSS를 불러오는 방식으로 적용
- **`el-dialog` 적용 — 지역별 도시 찾기 팝업, 필름 프레임 확대 뷰(`FilmLightbox`)**: 오버레이·ESC·포커스 트랩·스크롤 락·ARIA를 `el-dialog`가 처리. 열림 상태는 부모 값과 `v-model` 프록시로 연결하고, 팝업 내부 내용(칩 목록, 이미지 + ISO·톤)만 자체 마크업으로 채움
- **검색 입력을 `el-input`으로**: `clearable` 옵션으로 입력값 지우기 버튼과 포커스 스타일을 라이브러리가 처리하도록 함. 입력마다 상위로 값을 올리는 emit 구조는 그대로
- **Mock 데이터 알림을 `ElMessage`로**: 실시간 날씨를 받지 못해 Mock 데이터로 내려간 도시가 있으면 화면 상단에 토스트로 한 번 알림을 송부해서 UX를 개선함. 토스트의 위치·자동 사라짐·중첩 처리는 라이브러리가 해결하도록 설계함
- **날씨 배너·필름 스트립 이식**: 개인적으로 구현해보고 싶었던 필름 감성 화면을 도입함. `WeatherHero`는 선택한 도시의 날씨를 상징 배경(CSS 그라디언트 + 이모지)으로 보여주고, `FilmStrip`은 보유 필름 14종의 샘플 프레임을 가로로 나열함. 프레임에 마우스를 올리면 커서를 따라가는 원형 루페로 그 지점만 확대되고, 클릭하면 세부설명창이 열리도록 설계함

## 추가 확장 아이디어

1. 라이브러리에 넘길 상호작용과 자체로 남길 연출의 경계
2. 전역 등록과 번들 크기

### 상호작용과 연출의 경계

오버레이 생명주기·포커스 이동·키 처리·토스트 스택처럼 손으로 짜면 번거롭고 접근성까지 챙겨야 하는 자리는 `el-*`로 넘김. 반면 필름 프레임의 루페(커서 좌표로 배경 위치를 역산), 스트립의 드래그 스크롤(`scrollLeft` 직접 제어), 필름 그레인 질감은 라이브러리에 대응하는 컴포넌트가 없고 개인적으로 구현해보고 싶었던 요소라 자체 CSS·JS로 남김. 라이브러리 테마를 화면 전체에 입히면 지금까지 잡아둔 배색·흑백 토글과 부딪히므로 `el-*`는 전역 경로가 아닌 실제로 쓰이는 영역에만 배치함

### 전역 등록과 번들 크기

`ElementPlus` 전체를 `app.use()`로 등록하면 실제로 쓰는 컴포넌트가 서너 개여도 최종 번들에 라이브러리 전부가 들어감. 빌드 결과에서 벤더 청크와 CSS가 눈에 띄게 커짐(스크립트 기준 gzip 약 300KB). 강의가 전역 등록을 가르치므로 그대로 두되, 쓰는 컴포넌트만 자동으로 끌어오는 플러그인(`unplugin-vue-components`)으로 줄이는 방법이 있음을 확인.

## 의문점 정리

필름 프레임 SVG가 4KB 미만이라 빌드 시 파일이 아니라 data URI로 번들에 인라인됨. 루페 배경으로 쓸 때 따옴표 없는 `url()`에서 깨지는 걸 확인해 고쳤는데, 프레임을 더 정교하게 그려 4KB를 넘기면 파일로 분리되어 로딩 방식이 다시 달라지므로 인라인/분리 기준을 명시적으로 잡을지 검토가 필요함
